## 4. 端到端验证（真实样例 PDF，独立目录）

- 数据目录：独立 `INDEX_DIR`（系统临时目录），未覆盖或清理任何项目数据、未写入 `data/index/`。
- 真实入库：样例 `挖掘机维修案例(样例）.pdf` → `extract_text` 2025 字符 → `split_text` 7 chunks → `all-MiniLM-L6-v2`（384 维，首次需从 HuggingFace 下载权重，免费、无需 API Key）→ `build_index` + BM25。
- 持久化产物：`['bm25.json', 'chunks.json', 'faiss.index', 'manifest.json']`；`manifest.json` = `{version, embedding_model='all-MiniLM-L6-v2', chunk_size=400, chunk_overlap=40, num_chunks=7, faiss_index_type='FlatL2', built_at}`。
- 重启恢复：新进程经 FastAPI `lifespan` 加载 → `/api/status` `index_status=loaded`；真实查询 `encode_query("挖掘机维修")` 向量检索命中 `['c6','c0','c5']`，BM25 命中 `['c5','c3','c0']`。
- 负例：缺失 → `not_ready`；损坏 → `not_ready`；`CHUNK_SIZE` 不匹配 → `mismatch`（拒绝加载并提示重建）。

## 5. 延期项：`page` / `chunk_index`（WBS §5 :389）

- 事实：WBS P2.1 要点列举的 chunk 元数据为 `text / source / page / chunk_index`；当前仅持久化既有 `{source, doc_id}`（`text` 已随 `chunks.json` 的 `contents` 落盘）。
- 原因与依据：`page` 由 P2.2（Loader 按页 Block，:398–408）首次产生；`chunk_index` 的完整元数据契约归 P2.7（:468–476，§11.2 :953–960）。P2.1 落地时二者在实时管线中尚不存在。按本轮范围约束**不填虚假默认值**。
- 处理：P2.1 持久化为「元数据透传」——`save` 写全量 `metadatas_map`、`load` 原样恢复；后续阶段字段一旦产生即自动持久化，P2.1 无需再改。
- 风险：在 P2.2 / P2.7 完成前，持久化元数据不含 `page` / `chunk_index`。即：满足 P2.1「验收标准」三条，但未满足 P2.1「要点」的字段清单（记为有意延期）。
